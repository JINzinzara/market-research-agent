# 제품 범위와 현재 상태

**같은 UTC 구간의 시장 수치를 계산하고, 부분 실패를 기록·재현하는 로컬 첫 버전을 구현했다.** 반복 수요와 공개 서비스 운영은 검증하지 않았다.

## 지원 과제

BTCUSDT·ETHUSDT·BNBUSDT 현물을 비교한다. 기본 모드는 합성 자료를 사용하는 고정 흐름이며 외부 호출이 없다. 라이브 모드는 Binance 공개 API를 조회한다. Ollama 또는 OpenAI GPT-6 Astra는 별도 선택한 경우 계획 생성에만 사용한다. Astra에는 실행 프로세스의 OPENAI_API_KEY가 필요하며 실서비스 연결은 아직 검증하지 않았다. 수치·최종 설명은 Python에서 만든다.

API 문서 세 편의 검토 요약을 검색할 수 있지만, 뉴스 수집·가격 예측·매매·변동 원인 규명은 지원하지 않는다. 문서 검색은 관련 자료 제시까지만 수행하므로 질문 전체의 완료를 주장하지 않는다.

## 기간과 수치 계약

- `24h`: 최근 완료된 UTC 일봉 1개. `7d`: 최근 완료된 UTC 일봉 7개.
- 실행 시작의 timezone-aware `as_of`를 한 번 고정하고 UTC 날짜의 00:00을 종료 경계로 삼는다.
- 모든 종목에 `[start_utc, end_utc_exclusive)`를 적용한다. API의 `endTime`에는 종료 경계보다 1ms 작은 값을 보낸다.
- 명시적인 롤링 24시간·임의 날짜·지원하지 않는 기간은 확인 질문한다. 질문 문자열의 날짜로 임의 구간을 실행하지 않는다. CLI의 `--as-of`는 실행 재현용 기준 시각이다.
- 변화율은 `(마지막 완료 일봉 종가 / 첫 일봉 시가 − 1) × 100`이다. 40자리 Decimal 계산값과 소수 둘째 자리 HALF_UP 표시값을 별도 저장한다. 유한 정밀도이지 무한 정밀도가 아니다.
- 원 가격 문자열·일봉 12필드 배열·요청 URL·수집 시각을 보존한다. 일봉 수·시간 순서·중복·완료 시각·OHLC 양수·유한성·가격 범위를 검사한다.

합성 자료는 `2026-10-16T00:00:00Z`를 기준으로 고정돼 있다. 100·200·50 같은 입력은 테스트용이며 실제 과거 시세가 아니다. 합성 모드의 출처 URL은 실제 호출 주소를 보여주는 요청 명세이고, 네트워크에서 받은 자료라는 뜻이 아니다.

## 상태 판정

- `completed`: 요청한 시장 종목을 모두 계산했다. 일반적인 문장 이해·근거 적합성까지 자동 입증했다는 뜻은 아니다.
- `partial`: 요청한 여러 종목 중 일부만 계산했다. 실패 종목·오류를 함께 표시한다. HTTP 418/429를 받으면 남은 시장 요청도 중단하고 건너뛴 대상을 기록한다.
- `insufficient_evidence`: 문서 검색만 수행했거나, 계산 자료로는 원인 등 핵심 주장을 입증할 수 없다.
- `needs_clarification`: 대상·기간·구간 의미를 확인한다. 조사 HTTP 호출 없이 종료한다.
- `unsupported`: 지원 범위 밖 종목·예측·매매 등이다. 조사 HTTP 호출 없이 종료한다.
- `error`: 모든 요청 종목의 조회가 실패했거나 모델 계획 검증 등 실행이 실패했다.

`partial`을 스키마·런타임·화면·평가에 연결했다. 모든 수집 자료와 인용 ID의 연결을 검사하지만, 자유로운 문장의 의미적 근거 적합성 판정기는 없다.

## 화면과 완료 범위

조사 화면: 입력 → 모드 선택 → 결과 → 근거·실패 → 실행 상세·재현.

실행·평가 화면: 과거 기록 조회 → 원시 JSON → 현재 코드 재현 또는 개발용 평가.

두 화면이 같은 API와 조사 함수를 사용한다. 로컬 실행·정상/부분 실패·재현·20개 개발 사례까지 완료했다. 공개 배포·실사용 검증·수정 전후 비교·도구 선택 에이전트 비교는 후속 범위다.
